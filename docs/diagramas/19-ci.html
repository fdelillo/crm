Construcción y CI

Qué valida GitHub hoy y cómo se distribuirá la aplicación completa.

MixtoHTML autocontenido · sin conexiónVista doc-wide · audiencia técnica

CI actual del backend

Push a main o un pull request ejecuta el job de validación en GitHub Actions.

El workflow actual no publica ni despliega un artefacto. Su timeout es 20 min; las versiones Go y tools están fijadas en el repositorio.

Build completo previsto

El diseño agrega los checks y el build de frontend antes de compilar el binario con assets embebidos.

Secuencia prevista en T-F009/T-F701 y ADR-019/022. web/, estos targets y los jobs de frontend todavía no existen en el checkout.

Cómo leer esta vista

  • make lint comprueba gofmt, go vet con integration, golangci-lint/depguard y sqlc diff. make test usa go test -race; test-int agrega el tag integration.
  • Docker es necesario para integración; make check no requiere mkcert. El TLS de los tests HTTP lo proporciona httptest.NewTLSServer.
  • El diseño mantiene un único binario distribuible y versiones de frontend/backend alineadas. Node participa del build, no del servidor de producción.
  • El hosting, su proxy TLS, el despliegue automatizado y la política concreta de publicación permanecen pendientes en P-1. No se dibuja un proveedor elegido.
