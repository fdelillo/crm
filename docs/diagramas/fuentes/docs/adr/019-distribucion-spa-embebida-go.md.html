  44 ## Contexto
  45 
  46 La sesión es una cookie `__Host-` `HttpOnly` con protección CSRF basada en mismo origen (ADR-006):
  47 servir la SPA desde otro origen obligaría a rediseñar CORS y CSRF. El backend es un único binario
  48 (ADR-001). Una SPA con rutas de cliente necesita que el servidor devuelva `index.html` para
  49 cualquier ruta de la app, sin tapar los `404` de la API ni servir HTML en lugar de un JS
  50 inexistente. Tras cada deploy cambian los nombres con hash de los assets.
  51 
  52 ## Decisión
  53 
  54 - **Build**: `web/` → `npm run build` → `web/dist/`. Paquete Go `web` en la raíz del repo (fuera de
  55   `internal/`, porque `go:embed` necesita que `dist` esté bajo el paquete) con `//go:embed all:dist`
  56   y dos funciones: `DistFS() fs.FS` (el sub-FS `dist`) y `NewHandler(dist fs.FS) http.Handler`
  57   (recibe un `fs.FS` para poder probarlo con `fstest.MapFS`). `web/dist/` se ignora en git salvo
  58   `web/dist/.gitkeep`, así el backend compila y testea sin compilar el frontend; sin `index.html` el
  59   handler responde `503` con un texto que indica correr `make web-build`. `web` solo importa la
  60   librería estándar y `gzhttp`; solo `internal/app` y `cmd/crm` lo importan.
  61 - **Montaje fuera del router de la API** (plan DD-22, INV-22): `internal/app` arma un
  62   `http.ServeMux` raíz: `/api/` → router chi, `GET /healthz` y `GET /readyz` → ops, **todo lo
  63   demás** → `RootDeps.SPA`. Hasta T-F008, `RootDeps.SPA` es un stub que responde `503` con el mismo
  64   texto; T-F008 lo reemplaza por `web.NewHandler(web.DistFS())`. Los middlewares comunes (request
  65   id, recover, logging, cabeceras de seguridad y `CrossOriginProtection`) envuelven al mux raíz; los
  66   propios de la API (`no-store`, rate limit, sesión, permisos) quedan dentro de chi; los de la SPA
  67   (CSP, caché por tipo de archivo, gzip) dentro de `web`.
  68 - **Reglas del handler**: solo `GET`/`HEAD` (si no, `405`); archivo existente → se sirve; ruta con
  69   extensión que no existe → `404` texto plano con `no-store` (nunca `index.html`); cualquier otra
  70   ruta → `index.html` con `200`.
  71 - **Cabeceras de caché**: `index.html`, `sw.js`, `manifest.webmanifest`, `offline.html` →
  72   `no-cache`; `/assets/*` (con hash) → `public, max-age=31536000, immutable`; íconos → `public,
  73   max-age=86400`. Tabla completa (API, logo, ops y SPA) en `plan.md` §10.7.
  74 - **CSP** en los documentos HTML: `default-src 'self'; script-src 'self'; style-src 'self'
  75   'unsafe-inline'; img-src 'self' blob: data:; font-src 'self'; connect-src 'self'; manifest-src
  76   'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self';
  77   frame-ancestors 'none'`.
  78 - **Compresión** gzip **solo** del handler de la SPA (HTML, JS, CSS, manifest, service worker) con
  79   `github.com/klauspost/compress/gzhttp` y su umbral por defecto (1 KB); los íconos PNG y la API no
  80   se comprimen. Dependencia aprobada por el usuario (plan DD-29). Si el hosting pone un proxy que
  81   comprime, se quita.
  82 - **Desarrollo**: Vite en `:5173` con *proxy* de `/api` a `http://localhost:8080`, sin
  83   `changeOrigin` (mismo origen para el navegador); `APP_BASE_URL=http://localhost:5173` para que
  84   los enlaces de email abran Vite (el backend lo acepta con `COOKIE_SECURE=true`, DD-24). Para
  85   probar como en producción: `make build` y `crm serve`.
  86 - **Makefile**: `web-build` (`npm ci && npm run build` en `web/`), `web-check` (`npm run check`),
  87   `build` (`web-build` y después `go build`), `check-all` (`check` del backend + `web-check`).
  88 - **Errores de carga tras un deploy**: la SPA escucha `vite:preloadError` y recarga una vez.
  89 
  90 ## Fundamento
  91 
  92 - Mismo origen = la cookie viaja sola, `SameSite=Lax` y `Sec-Fetch-Site: same-origin` funcionan sin
  93   CORS; se mantiene todo ADR-006 sin cambios.
  94 - Un solo artefacto desplegable (constitución: monolito), versión de frontend y backend siempre
  95   alineadas: no hay un frontend nuevo hablando con una API vieja.
  96 - Montar la SPA fuera de chi deja intactos los tests que recorren las rutas de la API (cobertura de
  97   aislamiento con `chi.Walk`, rutas contra el contrato) y el `404 problem+json` de la API.
  98 - `no-cache` en `index.html` + `immutable` en assets con hash es la combinación estándar: cada
  99   carga ve el `index.html` nuevo, y los assets se descargan una sola vez por versión.
 100 - No servir `index.html` para archivos con extensión evita el error "MIME type text/html" y que un
 101   navegador cachee HTML como JS.
 102 - `script-src 'self'` sin inline es la parte de la CSP que realmente frena un XSS.
 103 - Comprimir solo estáticos públicos evita analizar ataques tipo BREACH sobre respuestas con datos
 104   personales (plan DD-29).

 106 ## Alternativas consideradas
 107 
 108 - **SPA en un CDN u otro dominio** (Vercel, Netlify, S3+CloudFront): despliegues separados y
 109   caché en el borde, pero exige CORS con credenciales y rediseñar CSRF (ADR-006 lo prohíbe sin un
 110   ADR nuevo); dos artefactos con versiones que pueden desalinearse.
 111 - **nginx/Caddy delante sirviendo `dist` y haciendo proxy a Go**: estándar, pero agrega un proceso
 112   y configuración que el hosting (P-1 del plan) todavía no define. Queda como opción si el hosting
 113   ya trae un proxy.
 114 - **Servir `dist` desde disco** (`http.Dir`) en vez de embebido: permite cambiar el frontend sin
 115   recompilar, pero el binario deja de ser autocontenido y la versión puede desalinearse.
 116 - **Registrar la SPA como ruta `/*` en chi**: más directo, pero rompe los tests de rutas del
 117   backend (T-B004, T-B801, ADR-014).
 118 - **Proxy de desarrollo del backend hacia Vite** (Go sirve todo y reenvía a `:5173`): un solo
 119   puerto, pero más código Go solo para desarrollo; el proxy de Vite viene incluido.
 120 - **CSP con *nonce*** para permitir estilos inline de forma estricta: requiere generar HTML por
 121   request (el `index.html` es estático); desproporcionado para el riesgo de estilos inline.
 122 - **gzip a mano con `compress/gzip`** o **archivos precomprimidos**: sin dependencia o sin CPU por
 123   request, pero con más lógica propia (`Accept-Encoding`, `Vary`, `ETag`, umbral) fácil de hacer
 124   mal (plan R-21).
 125 
 126 ## Consecuencias
 127 
 128 - Ganás: un binario que contiene todo, sesión y CSRF sin cambios, cabeceras de caché correctas,
 129   CSP estricta para scripts, estáticos comprimidos en cualquier hosting.
 130 - Aceptás: compilar el frontend antes que el binario de producción (Node en CI); cada deploy
 131   invalida los chunks viejos (mitigado con la recarga por `vite:preloadError`); la CSP no aplica en
 132   el servidor de desarrollo de Vite, así que sus violaciones se detectan en el E2E contra el
 133   binario; cambiar el montaje o las cabeceras exige tocar `internal/app` o `web` (código Go que
 134   implementa `backend-developer`); una dependencia Go más (`gzhttp`).
