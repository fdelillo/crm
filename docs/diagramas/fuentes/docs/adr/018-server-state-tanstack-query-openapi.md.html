   1 # ADR-018: Server state con TanStack Query, cliente openapi-fetch y tipos generados con openapi-typescript
   2 
   3 **Status**: Accepted (TanStack Query + openapi-fetch + openapi-typescript: decisión del usuario) · detalles (generación por spec con intersección, sin store global, defaults de caché, manejo global de 401): Proposed
   4 **Fecha**: 2026-09-29
   5 **Origen**: spec 001 (`ui.md` §10, §11, §12); implementa el paso de *bundle* de DD-17 y ADR-014
   6 
   7 ## Contexto
   8 
   9 Casi todo el estado de la app es del servidor: sesión, empresa, usuarios. Varias pantallas lo
  10 comparten, hay que invalidarlo tras cada cambio y un `401` en cualquier request significa "sesión
  11 vencida". El contrato OpenAPI 3.1 es canónico (ADR-014) y los tipos del cliente deben derivarse de
  12 él. Desde 002, cada spec tendrá su contrato y referenciará componentes de 001 con `$ref` externo
  13 (DD-17), así que hace falta un paso para generar tipos de todas las specs.
  14 
  15 ## Decisión
  16 
  17 - **TanStack Query v5** es el único lugar donde vive el server state. **No hay store global**
  18   (ni Redux, ni Zustand, ni Context de datos): lo que varias ramas necesitan (sesión, permisos,
  19   empresa) ya lo comparte la caché. Estado local con `useState`; formularios con React Hook Form.
  20 - **openapi-fetch** como cliente HTTP (`createClient<paths>`, `baseUrl` = origen + `/api/v1`,
  21   `credentials` del mismo origen). Todas las funciones de query/mutación pasan por `unwrap()`, que
  22   devuelve los datos o lanza un `ApiError` normalizado (`status`, `code`, `fieldErrors`,
  23   `suggestedAction`, `retryAfterSeconds`, `requestId`).
  24 - **openapi-typescript** genera los tipos: **un archivo por spec** (`src/api/generated/NNN.ts`)
  25   configurado en `web/redocly.yaml`, y `src/api/schema.ts` los combina por intersección
  26   (`paths = Paths001 & Paths002 & …`). Los archivos generados se versionan y `npm run lint` falla
  27   si están desactualizados. Si `openapi-typescript` no resolviera los `$ref` externos, se agrega un
  28   `redocly bundle` previo por spec (se valida en T-F004).
  29 - Alias legibles en `src/api/types.ts` (`type User = components['schemas']['User']`); **ningún tipo
  30   de API se escribe a mano**.
  31 - Defaults: `staleTime` 30 s; reintentos de queries solo ante errores de red y `503` (máx. 2);
  32   mutaciones sin reintento y con `networkMode: 'always'`; `refetchOnWindowFocus` activo.
  33 - **Manejo global** en `QueryCache.onError`/`MutationCache.onError`: `401 unauthenticated` →
  34   `queryClient.clear()` y login con `next`; `403 forbidden` → refrescar la sesión. La query de
  35   sesión mapea su `401` a `null` (anónimo). El callback se inyecta al crear el cliente.
  36 - Claves de caché en un único módulo (`src/api/queryKeys.ts`); cada mutación declara qué
  37   actualiza o invalida (tabla en `ui.md` §10.3).
  38 - Devtools de TanStack Query solo en desarrollo.
  39 
  40 ## Fundamento
  41 
  42 - La librería resuelve caché compartida, deduplicación, estados de carga, reintentos,
  43   invalidación y pausa sin conexión; hecho a mano con `useEffect` se reescribe peor en cada
  44   pantalla.
  45 - openapi-fetch no genera código: usa los tipos de `paths` directamente, así que una ruta o un
  46   campo inexistente es un error de compilación, con un cliente de ~pocos KB.
  47 - Un archivo por spec + intersección evita el paso de `join` (que tiene que resolver conflictos de
  48   nombres de componentes entre contratos) y deja diffs de tipos revisables por spec.
  49 - Un único manejador de `401` garantiza el mismo comportamiento en toda la app (ADR-006 pide que
  50   un `401` en cualquier request vuelva al login).
  51 
  52 ## Alternativas consideradas
  53 
  54 - **`fetch` en `useEffect` + estado propio**: sin dependencias, pero cada pantalla reimplementa
  55   carga, error, caché e invalidación; fuente clásica de datos desincronizados.
  56 - **SWR**: más simple, pero con menos control de mutaciones e invalidación por clave.
  57 - **RTK Query / Redux Toolkit**: potente, pero trae Redux y un store global que 001 no necesita.
  58 - **`openapi-react-query`** (hooks generados sobre openapi-fetch): menos código repetido, pero las
  59   claves de caché las arma la librería (menos explícitas para invalidar) y es una abstracción más.
  60 - **Generadores de clientes y hooks (orval, hey-api, openapi-generator)**: mucho código generado
  61   que el equipo tendría que leer y entender; más lejos de "la firma es el contrato".
  62 - **Redocly `join`** en un único contrato antes de generar: un solo archivo, pero con conflictos
  63   de nombres de componentes y `tags` entre specs a resolver en cada una.
  64 - **Tipos escritos a mano**: se desincronizan del contrato; violan ADR-014.
  65 - **Zustand para sesión**: la sesión es server state (`/me`); copiarla a un store obliga a
  66   sincronizarla a mano.
  67 
  68 ## Consecuencias
  69 
  70 - Ganás: tipos del contrato de punta a punta, un solo lugar para cada dato del servidor,
  71   comportamiento uniforme ante sesión vencida, nada que sincronizar a mano.
  72 - Aceptás: aprender el modelo de TanStack Query (claves, `staleTime`, invalidación); regenerar
  73   tipos con cada cambio de contrato (verificado por lint); una ruta repetida en dos specs se
  74   mezclaría en la intersección (lo detecta un test de tipos que exige claves disjuntas, T-F004).
